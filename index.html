Runtime Validation — NEW

Prove what was checked before execution.

Auditors ask: "how do you ensure outputs meet defined specifications?" The validate engine answers — before any tool call fires.

$ air-blackbox validate --tool=db_query \ --args='{"query":"DROP TABLE users"}' \ --allowlist=web_search,calculator ❌ content_policy BLOCK Dangerous pattern detected ❌ tool_allowlist BLOCK 'db_query' NOT on approved list ✅ pii_output_check INFO No PII detected in output ✅ hallucination INFO No indicators detected ❌ BLOCKED — action failed validation (0ms) Validation record: 8fb1e1f5.air.json

Every validation produces a signed .air.json record. Your evidence bundle now proves both: what was validated before execution (Article 15) and what happened during execution (Article 12).
